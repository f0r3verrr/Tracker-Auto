# Проект: трекер подбора автомобиля

## Задача
Веб-приложение для отслеживания процесса подбора автомобиля. Пользователь (я) собирает объявления с Авито, Дрома, Auto.ru, от дилеров — ведёт по каждому диалог, статус, оценку, отчёты по истории авто, фото. Нужен единый инструмент вместо разрозненных вкладок и переписок.

Один пользователь, без публичной регистрации. Редактирование данных должно быть доступно с любого устройства (сайт открывается и с телефона, и с ноутбука).

## Технологический стек

- **Frontend**: React + Vite + TypeScript
- **Стили**: Tailwind CSS
- **Backend/данные**: Supabase (Postgres + Storage + Auth)
- **Хостинг**: Vercel, автодеплой из GitHub-репозитория
- **Auth**: Supabase Auth, один пользователь (email+пароль или magic link), доступ к редактированию только после входа; просмотр можно оставить публичным или тоже закрыть логином — на усмотрение при реализации
- **PWA**: manifest.json + иконка, чтобы добавлять сайт на экран телефона

## Дизайн

Ориентир — карточные списки объявлений Авито / Auto.ru / Дром: чистая сетка карточек с фото, ключевыми характеристиками и ценой, слева/сверху панель фильтров, интуитивно понятная навигация без обучения. Требования:
- Адаптивная вёрстка (мобильный и десктоп)
- Карточка в списке: фото, марка/модель/год, цена, пробег, статус (цветной бейдж), оценка, платформа-источник
- Цветовая индикация статуса воронки и дилбрейкеров (см. ниже)
- Спокойная, не аляповатая палитра, крупные читаемые карточки, минимум visual noise

## Схема данных (Supabase / Postgres)

Таблица `cars`:

```sql
create table cars (
  id uuid primary key default gen_random_uuid(),
  created_at timestamptz default now(),
  updated_at timestamptz default now(),

  -- источник
  title text not null,
  url text,
  platform text, -- 'avito' | 'drom' | 'auto_ru' | 'dealer' | 'other'
  seller_contact text,

  -- цена
  price numeric,
  price_history jsonb default '[]', -- [{date, price}]

  -- владение
  year int,
  mileage int,
  owners_count int,
  tax numeric,
  condition text,
  pts text, -- оригинал/дубликат, электронный/бумажный
  customs text,
  exchange text,
  plate_number text,

  -- характеристики
  trim text,
  engine text,
  transmission text, -- MT/AT/robot/CVT
  drive_type text, -- FWD/RWD/AWD
  wheel text, -- left/right
  body_type text,
  color text,

  -- история / проверка
  vin text,
  owners_from_report int,
  had_accidents boolean,
  taxi_carsharing boolean,
  pledge_restrictions boolean,
  report_links jsonb default '[]', -- ссылки
  report_files jsonb default '[]', -- пути в Supabase Storage
  report_cost numeric,

  -- оценка и статус
  status text default 'new', -- new | contacted | report_ordered | called | viewed | negotiating | rejected | bought
  rating_overall int,
  rating_price int,
  rating_condition int,
  rating_honesty int,
  rating_seller_trust int,

  -- прочее
  tags text[] default '{}',
  comments jsonb default '[]', -- [{date, text}] — используется и как таймлайн-заметки
  next_contact_date date,
  archived boolean default false,
  photos jsonb default '[]' -- пути в Supabase Storage
);

create index on cars (status);
create index on cars (platform);
create index on cars (archived);
```

Таблица `activity_log` (для таймлайна, отдельно от ручных комментариев — фиксирует системные события типа изменения цены/статуса):

```sql
create table activity_log (
  id uuid primary key default gen_random_uuid(),
  car_id uuid references cars(id) on delete cascade,
  created_at timestamptz default now(),
  event_type text, -- 'price_change' | 'status_change' | 'comment' | 'created'
  details jsonb
);
```

Supabase Storage: два бакета — `car-photos` и `car-reports` (приватный, доступ только авторизованному пользователю).

Таблица `reviews` (отзывы/оценки от других людей — без регистрации):

```sql
create table reviews (
  id uuid primary key default gen_random_uuid(),
  car_id uuid references cars(id) on delete cascade,
  reviewer_id uuid not null, -- генерируется на клиенте при первом заходе, хранится в localStorage
  reviewer_name text not null,
  rating int,
  comment text,
  created_at timestamptz default now(),
  updated_at timestamptz default now(),
  owner_seen boolean default false -- прочитал ли владелец этот отзыв (для уведомлений в кабинете)
);

create index on reviews (car_id);
```

### RLS-политики

- `cars`: `select` — для ролей `anon` и `authenticated`; `insert/update/delete` — только для `authenticated` (владелец)
- `reviews`: `select` и `insert` — для `anon`; `update/delete` своей строки — разрешено гостю, только если переданный `reviewer_id` совпадает со значением в строке (проверка на уровне policy, не криптостойкая — для семейного некоммерческого использования этого достаточно); `update` поля `owner_seen` — только для `authenticated` (владелец отмечает отзывы прочитанными)
- Storage-бакеты `car-photos`/`car-reports`: чтение публичное (или по ссылке), запись — только `authenticated`

## Совместный просмотр и оценка без регистрации

Сайт нужно расшаривать родителям и знакомому — они должны видеть все карточки и оставлять свои оценки/комментарии, но без логина/пароля лично для себя.

- **Публичное чтение**: любой человек по ссылке видит список и карточки машин (через anon-доступ в Supabase, см. RLS выше)
- **"Кто ты?" при первом заходе**: небольшой экран выбора имени (Мама / Папа / [знакомый] / добавить своё имя). Выбор сохраняется в localStorage браузера (генерируется `reviewer_id` + сохраняется `reviewer_name`), больше не спрашивается на этом устройстве
- **Отзывы отдельно от основной оценки**: у каждой машины — твоя основная оценка (владелец, полный контроль данных) + список отзывов от остальных участников (имя, оценка, комментарий, дата), плюс агрегированное среднее по отзывам
- **Редактирование своего отзыва**: человек может изменить/удалить только свой отзыв (сверка по `reviewer_id` из localStorage)
- **Защита от случайных заходов по ссылке**: `robots.txt` с запретом индексации, meta `noindex`, опционально — единый код доступа на весь сайт (не персональный логин, просто общий пароль, вводится один раз и запоминается в localStorage)
- **UI**: бейдж в карточке списка вида "3 отзыва, ★7.3", блок "Мнения" на странице карточки со списком всех отзывов
- **Уведомления в кабинете владельца**: счётчик "N новых отзывов" на дашборде, точка-индикатор "новое" на карточках с непрочитанными отзывами в твоём (авторизованном) списке; при открытии карточки её отзывы автоматически помечаются просмотренными (`owner_seen = true`)

## Функционал

### Основные экраны
1. **Список карточек** — сетка, фильтры, сортировка, дашборд-сводка сверху
2. **Карточка автомобиля** — все поля, фото-галерея, история цены, таймлайн активности, комментарии, ссылки/файлы отчётов
3. **Форма добавления/редактирования** — все поля из схемы, сгруппированные блоками (Источник / Владение / Характеристики / История / Оценка) — по аналогии со скриншотом Auto.ru
4. **Сравнение** — выбор 2–4 машин, таблица характеристик side-by-side
5. **Вход владельца** — простая форма логина через Supabase Auth (только для тебя, для доступа к редактированию)
6. **"Кто ты?"** — экран выбора имени при первом заходе для гостей (родители/знакомый), без пароля, сохранение в localStorage

### Функции
- **Дашборд-сводка**: количество машин в работе по статусам, сумма потраченного на отчёты, средняя цена по активным, список "написать сегодня" (по `next_contact_date`), счётчик новых отзывов от родных/знакомого
- **Воронка статусов** с бейджами разных цветов
- **История цены**: при каждом изменении `price` — автоматически пишется запись в `price_history` и в `activity_log`
- **Разбивка оценки** по 4 критериям + автоматический общий рейтинг (среднее, либо ручной override)
- **Сравнение машин** — отдельная страница/модалка
- **Калькулятор реальной стоимости**: цена + оценочная стоимость ремонта (поле ввода) ± разница по налогу/страховке = итоговое сравнимое число
- **Экспорт/импорт JSON** — кнопка в настройках, полный бэкап таблицы `cars`
- **Чек-лист дилбрейкеров с подсветкой**: если `had_accidents`/`taxi_carsharing`/`pledge_restrictions` = true — красный маркер на карточке в списке
- **Таймлайн активности** внутри карточки — лента из `activity_log` + ручные `comments`, отсортированная по дате
- **Нормализованные метрики**: авторасчёт "цена за год возраста" (`price / (текущий_год - year)`) и "цена за 10к км" (`price / (mileage/10000)`), доступны как поля сортировки
- **Детект дублей**: при сохранении новой/изменённой карточки — проверка совпадения `vin` или `plate_number` с существующими записями, предупреждение с ссылкой на дубль
- **Файлы отчётов**: загрузка PDF/скринов в Supabase Storage (бакет `car-reports`), не только внешние ссылки
- **PWA**: manifest + service worker минимально для "добавить на экран"

### Фильтры (список)
- Платформа (мультивыбор)
- Цена (диапазон)
- Год выпуска (диапазон)
- Пробег (диапазон)
- Статус воронки (мультивыбор)
- Оценка (мин. значение)
- Теги (мультивыбор)
- Есть дилбрейкеры (переключатель вкл/выкл)
- Показывать архив (переключатель)

### Сортировка
По дате добавления, по цене, по оценке, по дате следующего контакта, по цене/год, по цене/10к км

## Порядок реализации

1. Инициализировать React + Vite + TS + Tailwind проект
2. Создать проект в Supabase, применить SQL-схему выше, настроить Storage-бакеты и Auth
3. Настроить переменные окружения (`.env`) для ключей Supabase, добавить `.env` в `.gitignore`
4. Экран логина + защита роутов редактирования
5. CRUD-слой (хуки/сервис для работы с `cars` и `activity_log`)
6. Список карточек + дашборд-сводка
7. Панель фильтров + сортировка
8. Форма добавления/редактирования (все блоки полей)
9. Карточка автомобиля (детали, галерея, таймлайн, история цены)
10. Логика дублей по VIN/госномеру
11. Экран сравнения
12. Экспорт/импорт JSON
13. PWA-манифест и иконка
14. Деплой на Vercel, подключение репозитория, настройка env-переменных в панели Vercel

## Что не делаем
- Парсинг/автозаполнение по ссылке с площадок объявлений (нестабильно, банится) — только ручной ввод
